## L. KNOWN ISSUES AND NOTES

1. **Contemporaneous DV is constant within firm-quarter.** CashHoldings is matched via merge_asof from the most recent Compustat filing. All calls in the same firm-quarter receive the same CashHoldings value. The table footnote (line 586) acknowledges this and directs interpretation alongside the lead DV.

2. **Industry FE uses `check_rank=False`.** For the industry FE specs, `check_rank=False` is passed to `PanelOLS` (line 373). This suppresses rank-deficiency warnings that can arise from collinear absorbed effects. The firm FE specs do not set this flag (use default `True`).

3. **Lagged DV construction uses fiscal year, not calendar year.** The `Lagged_DV` control is `CashHoldings_lag`, which is the previous fiscal year's end-of-year CashHoldings (from the latest call in that fiscal year). This correctly handles non-December fiscal year-end firms (~30% of sample). The lag requires consecutive fiscal years; gaps produce NaN.

4. **Lead variable fiscal year continuity validation.** `CashHoldings_lead` is set to NaN if the firm's next fiscal year is not exactly fyearq + 1 (line 331 of the panel builder). This prevents assigning misleading lead values across fiscal year gaps.

5. **Docstring comment mismatch.** Runner line 794 says "8 model specifications" but there are 12 MODEL_SPECS (verified at line 105--119). This is a stale comment.

6. **Attrition table labels partially misleading.** The runner's attrition table (lines 823--828) labels step 3 as "After lead filter (col 5-8 only)" but the lead DV actually applies to cols 7--12 (not 5--8). The label is inaccurate.

7. **Linguistic winsorization is upper-only (0%/99%).** The LinguisticEngine uses `lower=0.0, upper=0.99` (line 257 of `_linguistic_engine.py`). This means the lower bound is 0th percentile (no left-tail clipping), and only the 99th percentile upper bound is applied. The Compustat and CRSP engines use symmetric 1%/99%.

8. **CRSP Volatility window definition.** The Volatility window runs from [call start_date + 1 day] to [next_call_date - 5 days], not from [prev_call_date + 5 days] as stated in `volatility.py`'s docstring (line 7). The docstring is misleading; the actual code at `_crsp_engine.py` lines 361--366 uses `start_date + DAYS_AFTER_CURRENT_CALL` (1 day) and `next_call_date - DAYS_BEFORE_NEXT_CALL` (5 days). This represents a POST-call window looking forward to the next call.

9. **Computed-but-unused variables in panel.** The panel builder (`build_h1_cash_holdings_panel.py`) imports and executes three builders that produce columns in the Stage 3 parquet file but are not referenced in any H1 regression specification:
   - `CurrentRatioBuilder` (lines 78, 152): produces `CurrentRatio = actq / lctq`
   - `AnalystQAUncertaintyBuilder` (lines 137--139): produces `AnalystQA_Uncertainty_pct`
   - `NegativeSentimentBuilder` (lines 140--142): produces `NegativeSentiment_pct`

   None of these appear in `run_h1_cash_holdings.py` (`KEY_IVS`, `BASE_CONTROLS`, or `EXTENDED_CONTROLS`). They are present in the parquet and do not affect regression results. They may be retained for downstream reuse by other suites.

10. **Stale module-level docstring in panel builder.** Lines 16--18 of `build_h1_cash_holdings_panel.py` describe the `CashHoldings_lead` construction as "Average CashHoldings within (gvkey, call_year) -> firm-year mean". This description is stale and incorrect relative to the actual code. The function `create_lead_variable()` (lines 308--334) uses `idxmax()` to select the LATEST call within each `(gvkey, fyearq_int)` group, not an average. The module-level docstring has not been updated to reflect this fiscal-year fix.

11. **IBES listed as raw input in builder docstring but not used.** Builder docstring line 31 lists `inputs/tr_ibes/tr_ibes.parquet` (IBES data) as a raw input dependency. No IBES engine, IBES builder, or `IbesEngine` class is imported or called anywhere in `build_h1_cash_holdings_panel.py`. This is a stale artifact. The H1 suite does not use IBES data.
