## A. SUITE IDENTITY
------------------------------------------------------------------------

```yaml
Suite ID:        H11
Title:           Political Risk and Language Uncertainty
Hypothesis:      Does higher quarterly political risk exposure increase language uncertainty in earnings call speech?
Direction:       one-tailed beta > 0
Model Family:    PanelOLS
Estimator:       linearmodels.panel.PanelOLS
Unit of Obs:     call-level
Panel Index:     (gvkey, year)
Columns:         4 (Main sample only; 12 total regressions across 3 samples)
Reference:       Hassan, Hollander, van Lent, Tahoun (2019) "Firm-Level Political Risk: Measurement and Effects"
Runner:          src/f1d/econometric/run_h11_prisk_uncertainty.py
Panel Builder:   src/f1d/variables/build_h11_prisk_uncertainty_panel.py
```

**Key Design Note:** H11 REVERSES the standard IV/DV relationship used
in the other thesis suites. In the standard suites, linguistic uncertainty
is the IV and financial outcomes are the DV. In H11, the linguistic
uncertainty measures are the DVs and quarterly political risk (PRiskQ) is
the single IV. This tests whether political risk drives speech uncertainty
rather than the other way around.

## B. MODEL SPECIFICATION
------------------------------------------------------------------------

### B1. Regression Equation

```
Uncertainty_{i,t} = b1 * PRiskQ_{i,t} + b2 * Analyst_QA_Uncertainty_pct_{i,t}
                    + [b3 * Pres_Uncertainty_pct_{i,t}]
                    + b4 * Entire_All_Negative_pct_{i,t}
                    + b5 * Size_{i,t} + b6 * TobinsQ_{i,t} + b7 * ROA_{i,t}
                    + b8 * CashHoldings_{i,t} + b9 * DividendPayer_{i,t}
                    + b10 * firm_maturity_{i,t} + b11 * earnings_volatility_{i,t}
                    + alpha_i + gamma_t + epsilon_{i,t}
```

Where:
- `alpha_i` = firm fixed effects (EntityEffects on gvkey)
- `gamma_t` = time fixed effects (TimeEffects on year)
- The bracketed `[Pres_Uncertainty_pct]` term is dynamically added ONLY when the DV is a QA measure (see B4 for dynamic control logic)

### B2. Dependent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| Manager_QA_Uncertainty_pct | Manager Q&A uncertainty word % | (uncertainty word count / total word count) * 100 for Manager Q&A section | LinguisticEngine (Stage 2) | Contemporaneous (t) |
| CEO_QA_Uncertainty_pct | CEO Q&A uncertainty word % | (uncertainty word count / total word count) * 100 for CEO Q&A section | LinguisticEngine (Stage 2) | Contemporaneous (t) |
| Manager_Pres_Uncertainty_pct | Manager presentation uncertainty word % | (uncertainty word count / total word count) * 100 for Manager Pres section | LinguisticEngine (Stage 2) | Contemporaneous (t) |
| CEO_Pres_Uncertainty_pct | CEO presentation uncertainty word % | (uncertainty word count / total word count) * 100 for CEO Pres section | LinguisticEngine (Stage 2) | Contemporaneous (t) |

All four DVs are Loughran-McDonald uncertainty word percentages computed
per-speaker per-section in Stage 2 textual analysis.

### B3. Independent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| PRiskQ | Quarterly political risk exposure | Raw PRisk from Hassan et al. (2019) firmquarter file, matched by (gvkey, calendar_quarter). Deduplicated: max PRisk per (gvkey, cal_q). Winsorized 1%/99% by year. | Hassan et al. (2019) via PRiskQBuilder; source file: `inputs/FirmLevelRisk/firmquarter_2022q1.csv` (tab-separated) | Contemporaneous (same calendar quarter Q as the call) |

PRiskQ is the ONLY IV in this suite. No centering, log-transform, or
z-scoring is applied. The variable is matched contemporaneously: the
earnings call occurs in calendar quarter Q and PRiskQ measures political
risk exposure for the same quarter Q.

### B4. Control Variables

**Base Controls (always included):**

| Variable Name (code) | Description | Formula | Source Engine |
|---|---|---|---|
| Analyst_QA_Uncertainty_pct | Analyst Q&A uncertainty word % | (uncertainty word count / total word count) * 100 for Analyst QA section | LinguisticEngine (Stage 2) |
| Entire_All_Negative_pct | Entire-call negative sentiment % | (negative word count / total word count) * 100 for entire call | LinguisticEngine (Stage 2) |
| Size | Firm size (log total assets) | ln(atq), atq > 0 required | CompustatEngine: atq |
| TobinsQ | Tobin's Q | (cshoq * prccq + debt_book) / atq | CompustatEngine: cshoq, prccq, dlcq, dlttq, atq |
| ROA | Return on assets | iby_annual (Q4) / avg_assets, where avg_assets = (atq_t + atq_{t-1}) / 2 | CompustatEngine: iby, atq |
| CashHoldings | Cash and equivalents ratio | cheq / atq | CompustatEngine: cheq, atq |
| DividendPayer | Dividend payer indicator (binary) | 1 if dvy_annual (Q4 full-year) > 0, else 0 | CompustatEngine: dvy, fqtr, fyearq |
| firm_maturity | Firm maturity (RE/TA) | req / atq (annual, from Q4 row) | CompustatEngine: req, atq, fyearq |
| earnings_volatility | Earnings volatility | Rolling 5-year std of annual ROA (iby/atq), min 3 years | CompustatEngine: iby, atq, fyearq |

**Dynamic Presentation Control (conditional):**

| Variable Name (code) | Added When DV Is | Description |
|---|---|---|
| Manager_Pres_Uncertainty_pct | Manager_QA_Uncertainty_pct | Controls for manager's prepared remarks uncertainty when DV is manager Q&A uncertainty |
| CEO_Pres_Uncertainty_pct | CEO_QA_Uncertainty_pct | Controls for CEO's prepared remarks uncertainty when DV is CEO Q&A uncertainty |
| (none) | Manager_Pres_Uncertainty_pct | No Pres control added when DV is already a Pres measure |
| (none) | CEO_Pres_Uncertainty_pct | No Pres control added when DV is already a Pres measure |

**Dynamic control logic (code reference: `PRES_CONTROL_MAP` dict, lines 106-111 of the runner; invoked by `prepare_regression_data()` at line 153-155):**

When the DV is a QA measure, the corresponding Presentation measure for
the same speaker role is automatically appended to the controls list. This
controls for the fact that a manager who uses more uncertainty words in
prepared remarks will likely also use more in Q&A, independent of political
risk. When the DV is already a Presentation measure, no additional Pres
control is added (value is `None` in the map).

**Note on Lagged DV:** H11 does NOT include a lagged DV control. There is
no `Lagged_DV` row because the panel index uses `year` (not `cal_yr_qtr`),
and the runner does not construct or include any lagged dependent variable.

### B5. Fixed Effects

| FE Type | Column Used | Description |
|---|---|---|
| Entity | gvkey | Firm fixed effects (absorbed via PanelOLS EntityEffects) |
| Time | year | Calendar year FE (absorbed via PanelOLS TimeEffects) |

**Important:** H11 uses `year` as the time index, NOT `cal_yr` or
`cal_yr_qtr`. The `year` column is derived from `start_date.dt.year` in
the panel builder (line 149 of build_h11_prisk_uncertainty_panel.py). The
panel is set with `df_panel = df_sample.set_index(["gvkey", "year"])`
(runner line 191). PanelOLS absorbs both entity (gvkey) and time (year)
effects via `EntityEffects + TimeEffects` in the formula string (runner
line 176-179).

### B6. Standard Errors and Clustering

- **cov_type:** `"clustered"` (runner line 195)
- **Clustering dimension:** Entity only (`cluster_entity=True`, runner line 195)
- **Cluster variable:** gvkey (firm-level clustering)
- **Small-sample corrections:** PanelOLS default (no additional corrections specified)

### B7. Hypothesis Test

- **Direction:** One-tailed, beta(PRiskQ) > 0
- **Interpretation:** Higher political risk exposure increases speech uncertainty
- **P-value computation:** Two-tailed p from PanelOLS is halved for the correct tail direction:
  - If `beta_prisk > 0`: `p_one = p_two / 2`
  - If `beta_prisk <= 0`: `p_one = 1 - p_two / 2`
  - (Runner lines 211-213)
- **Significance thresholds (from LaTeX table formatter, lines 261-266):**
  - `***` p < 0.01
  - `**` p < 0.05
  - `*` p < 0.10
- **H11 significance criterion:** `p_one < 0.05 AND beta_prisk > 0` (runner line 216)

### D2. Exclusion Criteria

The runner applies filters in this order:

| Step | Filter | Description |
|---|---|---|
| 1 | Full manifest | All calls in master_sample_manifest.parquet for configured year range |
| 2 | Sample assignment | `assign_industry_sample(ff12_code)`: FF12=11 -> Finance, FF12=8 -> Utility, all others -> Main |

| 5 | Min calls filter | Firms with < 5 calls within the sample are excluded (`gvkey_count >= 5`, runner lines 476-481) |
| 6 | Minimum N check | If filtered sample has < 100 rows, regression is skipped entirely (runner line 487) |

**Attrition cascade (as coded in runner lines 509-514):**

| Step | Stage | Rows |
|---|---|---|
| 1 | Master manifest | len(panel) |
| 2 | Main sample filter | (panel["sample"] == "Main").sum() |
| 3 | After complete-case + min-calls filter | n_obs from regression output |

Note: Exact row counts are runtime-dependent and determined by the data.
The attrition cascade is generated by `generate_attrition_table()` and
written to `sample_attrition.csv` and `sample_attrition.tex`.

### D3. Sample Counts per Specification

N varies across the 4 published columns because:
1. Different DVs have different missingness patterns (e.g., a call may have
   CEO Q&A data but not Manager Pres data).
2. QA DVs have an extra control (Pres measure) which adds one more required
   non-missing column, potentially dropping more rows.

Exact N per column is written to `model_diagnostics.csv` at runtime.

## F. DATA PIPELINE
------------------------------------------------------------------------

### F1. Dependency Chain

1. **Raw inputs:**
   - `inputs/FirmLevelRisk/firmquarter_2022q1.csv` (Hassan et al. 2019 quarterly PRisk, tab-separated)
   - `inputs/comp_na_daily_all/comp_na_daily_all.parquet` (Compustat quarterly)
   - `outputs/1.4_AssembleManifest/latest/master_sample_manifest.parquet` (Stage 1 manifest)
   - `outputs/2_Textual_Analysis/2.2_Variables/latest/linguistic_variables_{year}.parquet` (Stage 2 linguistic vars)

2. **Engine loading:**
   - **LinguisticEngine** (singleton): loads year-partitioned Stage 2 parquets, applies per-year 0%/99% upper-only winsorization to all `_pct` columns, caches result.
   - **CompustatEngine** (singleton): loads raw Compustat quarterly, computes Size, TobinsQ, ROA, CashHoldings, DividendPayer, firm_maturity, earnings_volatility (and many others), applies per-fyearq 1%/99% winsorization, caches result.
   - **PRiskQBuilder**: loads Hassan PRisk CSV, parses calendar quarters, winsorizes 1%/99% by year, merges to manifest by (gvkey, cal_q).

3. **Panel builder (`build_h11_prisk_uncertainty_panel.py`):**
   - Load manifest fields (file_name, gvkey, ff12_code, start_date, etc.)
   - Build each variable via its builder (16 builders total)
   - Merge each builder's output onto manifest by `file_name` (left join, zero row-delta enforced)
   - Assign industry sample via `assign_industry_sample(ff12_code)`
   - Derive `year` from `start_date.dt.year` and `cal_q` for reference
   - Save panel parquet

4. **Runner loading (`run_h11_prisk_uncertainty.py`):**
   - Load panel parquet with explicit column selection (17 columns + file_name)
   - If `sample` column missing, recompute via `assign_industry_sample`

5. **Sample filtering:**
   - Per DV: `prepare_regression_data()` builds required column list, replaces inf with NaN, drops NaN rows
   - Per sample: filter to Main/Finance/Utility
   - Per firm: min 5 calls filter
   - Minimum 100 observations check before running regression

6. **Regression estimation:**
   - PanelOLS with firm + year FE and firm-clustered SEs
   - One-tailed p-value computed from two-tailed
   - Results saved to individual `.txt` files per (sample, DV)

7. **Table generation:**
   - `_save_latex_table()` in runner builds a 4-column LaTeX table (Main sample only)
   - `generate_all_tables.py` picks up results via moderation-type entry for final formatting

## H. OUTLIER AND MISSING DATA TREATMENT
------------------------------------------------------------------------

### H1. Winsorization

**Compustat financial variables** (Size, TobinsQ, ROA, CashHoldings, firm_maturity, earnings_volatility):
- Level: 1%/99% per fiscal year (fyearq), at CompustatEngine level
- Applied via `_winsorize_by_year()` inside `_compute_and_winsorize()`
- Inf values replaced with NaN before winsorization

**DividendPayer:**
- NOT winsorized (binary variable, excluded from `winsorize_cols` in CompustatEngine)

**Linguistic variables** (all `_pct` columns including all DV uncertainty measures, Analyst_QA_Uncertainty_pct, Entire_All_Negative_pct):
- Level: 0%/99% upper-only per-year (year from filename), at LinguisticEngine level
- Applied via `winsorize_by_year()` with `lower=0.0, upper=0.99, min_obs=10`
- These are bounded [0, 100] by construction; only upper tail is trimmed

**PRiskQ:**
- Level: 1%/99% per year, applied in PRiskQBuilder
- Applied via `winsorize_by_year(prisk_df, ["PRisk"], year_col="year")` (prisk_q.py line 141)
- Uses default parameters: `lower=0.01, upper=0.99, min_obs=10`

### H2. Missing Data Policy

- **Complete-case deletion:** `prepare_regression_data()` drops rows where ANY required variable (DV, PRiskQ, all controls, gvkey, year) is NaN (runner line 164)
- **Inf replacement:** `panel.replace([np.inf, -np.inf], np.nan)` applied before dropna (runner line 164)
- **PRiskQ matching:** Calls without a matching (gvkey, cal_q) in the Hassan dataset receive NaN for PRiskQ and are dropped during complete-case filtering

### H3. Transformations

- **Size:** Natural log transformation of atq (ln(atq))
- No other transformations (no centering, z-scoring, or standardization) are applied to any variables in the runner code. The LaTeX table notes state "All continuous controls are standardized" but the code does NOT apply standardization -- this is a **documentation inconsistency** (code is truth).

### K1. PanelOLS Specifics

- **R-squared reporting:** The runner computes both R-squared (`model.rsquared`) and adjusted R-squared (`1 - (1 - model.rsquared) * (model.nobs - 1) / model.df_resid`) manually (runner lines 202, 231-232). Note: `model.rsquared` from PanelOLS with entity/time effects is the within R-squared.

## L. KNOWN ISSUES AND NOTES
------------------------------------------------------------------------

1. **LaTeX table note inconsistency (documentation vs code):** The LaTeX table notes (runner line 357) state "All continuous controls are standardized" but the runner code does NOT apply any standardization or z-scoring to controls before regression. The code is the source of truth: variables enter the regression in their raw (winsorized) units.

2. **BookLevBuilder imported but unused:** The panel builder imports and builds `BookLevBuilder` (line 109 of build_h11_prisk_uncertainty_panel.py), so the `BookLev` column exists in the parquet panel, but it does not appear in `BASE_CONTROLS` or any regression specification in the runner. This is dead weight in the panel but does not affect results.

3. **Three samples, one published table:** The runner estimates 12 regressions (4 DVs x 3 samples) but the LaTeX table only includes the 4 Main-sample models. Finance and Utility results are available in individual `.txt` files but are not formatted into the published table. The `generate_all_tables.py` entry also only references 4 columns (Main sample).

4. **No Lagged DV control:** Unlike most other suites in this thesis, H11 does not include a lagged DV as a control variable. This is a design choice consistent with the reverse-causality framing: PRiskQ is external (macro political risk) and should not require controlling for prior uncertainty levels.

5. **Year FE vs Cal_Yr FE:** H11 uses `year` (derived from `start_date.dt.year` in the panel builder) as the time FE index, not `cal_yr` or `cal_yr_qtr` used by other suites. Since `year` is derived from the call's `start_date`, it is effectively the calendar year, but the column name is `year` not `cal_yr`. The panel index is `(gvkey, year)`.

6. **PRiskQ is contemporaneous (no lag):** PRiskQ is matched to calls in the same calendar quarter. The Hassan et al. (2019) data measures political risk exposure during quarter Q, and the call occurs during the same quarter Q. There is no temporal lead or lag in the main H11 specification (separate H11-Lag and H11-Lead suites handle temporal displacement).

7. **Minimum calls threshold:** Firms must have >= 5 calls within the filtered sample (after sample split and complete-case filtering) to be included. This is applied per sample independently (runner lines 476-481).

8. **Adj R-squared manually computed:** The runner computes adjusted R-squared with `1 - (1 - model.rsquared) * (model.nobs - 1) / model.df_resid` rather than using a built-in attribute, to ensure a consistent definition across the thesis.
