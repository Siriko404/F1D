## B. MODEL SPECIFICATION
------------------------------------------------------------------------

### B1. Regression Equation

```
CCCL_{i,t} = b1*UncAnsCEO + b2*UncPreCEO
           + b3*UncAnsMgr + b4*UncPreMgr
           + Controls + alpha_j + gamma_t + epsilon_{i,t}
```

Where:
- `alpha_j` = Industry (FF12) FE (odd columns) or Firm FE (even columns)
- `gamma_t` = Calendar Year FE (cols 1-4) or Calendar Year-Quarter FE (cols 5-6)
- `i` = individual earnings call, `t` = calendar year or calendar year-quarter
- LPM: binary DV estimated with OLS (PanelOLS), not logit/probit

### B2. Dependent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| CCCL | Binary: firm received SEC comment letter in next calendar quarter | 1 if `(gvkey, cal_qtr_id+1)` exists in CCCL event set; 0 otherwise | CCCL input file + CIK-gvkey map | Lead (Q+1) |

**Construction detail** (from `build_h18_cccl_received_panel.py`, function `create_cccl_dvs`, lines 231-287):
1. Load SEC comment letters from `inputs/Conference Calls Comment Letters/cccl_conversations_all_years.parquet` (1,183 letters, 1,090 unique CIKs, filing dates 2005-2022).
2. Link CIK to gvkey via combined CCM linktable + Compustat direct CIK field (integer CIK comparison to avoid zero-padding issues).
3. Build set of `(gvkey, cal_qtr_id)` tuples where the firm received at least one comment letter, with `cal_qtr_id = year*10 + quarter` derived from filing_date.
4. For each call at date `d` in calendar quarter `Q`: `CCCL = 1` if `(gvkey, Q+1)` is in the event set; `0` otherwise.
5. Base rate in main sample: 280/88,205 = 0.317%.

### B3. Independent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| UncAnsCEO | CEO Q&A uncertainty word percentage | (Uncertainty word count / total word count) * 100, CEO Q&A section | LinguisticEngine (Stage 2 outputs) | Contemporaneous (t) |
| UncPreCEO | CEO presentation uncertainty word percentage | (Uncertainty word count / total word count) * 100, CEO presentation section | LinguisticEngine (Stage 2 outputs) | Contemporaneous (t) |
| UncAnsMgr | All-manager Q&A uncertainty word percentage | (Uncertainty word count / total word count) * 100, all managers Q&A section | LinguisticEngine (Stage 2 outputs) | Contemporaneous (t) |
| UncPreMgr | All-manager presentation uncertainty word percentage | (Uncertainty word count / total word count) * 100, all managers presentation section | LinguisticEngine (Stage 2 outputs) | Contemporaneous (t) |

All four IVs are bounded [0, ~2.5] by construction (percentage of Loughran-McDonald uncertainty words). Winsorized per-year 0%/99% (upper-only) at LinguisticEngine level.

### B7. Hypothesis Test

- Direction: **one-tailed (beta > 0)** -- higher uncertainty predicts more SEC scrutiny
- P-value computation (runner lines 310-313):

## K. MODEL-FAMILY ADDENDUM
------------------------------------------------------------------------

### K1. PanelOLS Specifics (LPM)

This suite uses PanelOLS as a Linear Probability Model (LPM) for a binary DV. The binary DV (CCCL in {0, 1}) is estimated with linear regression rather than logit/probit.

**Methodological justification** (runner docstring lines 28-32):
- Timoneda (2021, Social Science Research): Monte Carlo evidence shows LPM-FE outperforms logit at base rates <5%.
- At ~0.3% treatment rate, heteroscedasticity is negligible (Var = p(1-p) ~ 0.003), linearity approximation is excellent, no incidental parameters problem (which affects logit with firm FE), no sample loss from perfect prediction in thin groups.

**Entity effects**:
- Industry FE (odd cols): absorbed via `other_effects=df_panel["ff12_code"]`, `entity_effects=False`, `time_effects=True` (runner lines 270-278)
- Firm FE (even cols): absorbed via `EntityEffects` in PanelOLS formula, `TimeEffects` (runner lines 282-283)
- `drop_absorbed=True` in all specifications (runner lines 277, 283)

**Time effects**: absorbed via `time_effects=True` (industry specs) or `TimeEffects` in formula (firm specs). Panel index time dimension is `cal_yr` (cols 1-4) or `cal_yr_qtr` (cols 5-6), determined at runner line 249.

**Singleton handling**: PanelOLS default behavior. `check_rank=False` set for industry FE specs (runner line 277).

**R-squared reporting**: Both R-squared and Adjusted R-squared are reported. Adj R-squared is computed manually as `1 - (1 - R2) * (nobs - 1) / df_resid` (runner line 300). Note: R-squared values are very small (0.0003-0.0014) as expected for a rare binary DV with call-level observations.

## L. KNOWN ISSUES AND NOTES
------------------------------------------------------------------------

1. **Very low R-squared**: R-squared ranges from 0.0003 to 0.0014 across specifications. This is expected for a rare binary DV (~0.3% base rate) at call-level granularity. Adjusted R-squared is negative in all specifications due to FE absorption with minimal explained variance.

2. **CCCL base rate**: Only 280 of 88,205 main-sample calls have CCCL=1 (0.32%). This extremely rare event is precisely why LPM is preferred over logit -- logit with firm FE would drop firms with all-zero outcomes (perfect prediction), losing substantial sample. Timoneda (2021) provides the methodological justification.

3. **CIK-gvkey linkage coverage**: The panel builder's docstring notes ~330 of 693 linked CCCL letters come from firms in the earnings call manifest. Coverage is limited because many CCCL recipients are not in the S&P 1500/Russell universe that dominates the earnings call sample.

4. **LaTeX table column header**: The runner's LaTeX table uses `CCCL_fwd (call-to-next-call)` as the DV label (runner line 381), while the regression uses column name `CCCL`. The `_fwd` suffix in the table label clarifies the forward-looking nature of the DV.

5. **Attrition table "CCCL=1 in Main" row**: The attrition table includes an informational row showing CCCL=1 count (280) which is not an exclusion step. It is included for context on the event rate, not as a filter.

6. **fyearq_int in required columns**: The runner requires `fyearq_int` in the `required` list (line 202) for all specifications, but it is not directly used in the regression formula. It is carried through as a panel metadata field. The time FE column is `cal_yr` or `cal_yr_qtr`, not `fyearq_int`.

7. **Runner docstring contradicts builder implementation**: Runner docstring (lines 10-11) describes the DV window as "received SEC comment letter **between this call and the next call** / Window: (start_date_current, start_date_next_call]." This implies a call-to-call time window. However, `create_cccl_dvs()` in the panel builder implements a **next calendar quarter (Q+1)** lookup: `cccl_fwd[i] = 1.0 if (g, q_next) in cccl_set else 0.0` where `q_next = _next_cal_qtr(q)`. The builder's calendar-quarter implementation is the operative code. The runner docstring is incorrect and should be updated.
