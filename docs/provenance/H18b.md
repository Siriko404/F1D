## B. MODEL SPECIFICATION
------------------------------------------------------------------------

### B1. Regression Equation

```
P(CCCL_{i,t} = 1 | X) = Lambda(
    b1*CEO_QA_Uncertainty_pct + b2*CEO_Pres_Uncertainty_pct
    + b3*Manager_QA_Uncertainty_pct + b4*Manager_Pres_Uncertainty_pct
    + Controls + C(ff12_code) + C(cal_yr)
)
```

Where:
- `Lambda(.)` = logistic CDF (sigmoid function)
- `C(ff12_code)` = industry dummies (FF12), included as Patsy formula categorical
- `C(cal_yr)` = calendar year dummies, included as Patsy formula categorical
- `i` = individual earnings call
- `t` = calendar year (derived from call start_date)
- Coefficients reported as **Average Marginal Effects** (AMEs), not log-odds
- `b1`–`b4` represent change in P(CCCL=1) for a one-unit increase in the IV

**FE note** (runner docstring lines 19-26):
- Firm FE excluded: ~95% of firms have CCCL=0 for all observations, causing perfect separation and the incidental parameters problem (Neyman-Scott 1948).
- Year-Quarter FE excluded: 26 of 67 quarters have zero CCCL events, guaranteeing perfect separation on those quarter dummies.
- Only Industry FE + Calendar Year FE are feasible given the ~0.3% base rate.

### B2. Dependent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| CCCL | Binary: firm received SEC comment letter in next calendar quarter | 1 if `(gvkey, cal_qtr_id+1)` exists in CCCL event set; 0 otherwise | CCCL input file + CIK-gvkey map | Lead (Q+1) |

**Construction detail** (from `build_h18_cccl_received_panel.py`, function `create_cccl_dvs`, lines 231-287):
1. Load SEC comment letters from `inputs/Conference Calls Comment Letters/cccl_conversations_all_years.parquet`.
2. Link CIK to gvkey via combined CCM linktable + Compustat direct CIK field (integer CIK comparison to avoid zero-padding issues).
3. Build set of `(gvkey, cal_qtr_id)` tuples where the firm received at least one comment letter, with `cal_qtr_id = year*10 + quarter` derived from `filing_date`.
4. For each call at date `d` in calendar quarter `Q`: `CCCL = 1` if `(gvkey, Q+1)` is in the event set; `0` otherwise.
5. This is a calendar-quarter lookup, not a call-to-call window.

**Same panel as H18 LPM**: H18b reuses `h18_cccl_received_panel.parquet` without any new variable construction (runner docstring lines 7-9).

### B5. Fixed Effects / Stratification

Both columns use the same FE structure (runner `MODEL_SPECS`, lines 91-94):

| FE Type | Specification in Formula | Description |
|---------|--------------------------|-------------|
| Industry | `C(ff12_code)` | Fama-French 12-industry dummy variables in Patsy formula |
| Calendar Year | `C(cal_yr)` | Calendar year dummy variables in Patsy formula |

Fixed effects are entered as formula-based dummy variables via Patsy/statsmodels, not absorbed via PanelOLS. This is the only feasible approach given the extreme rarity of events (runner docstring lines 19-26).

There are no firm FE or year-quarter FE columns (see B1 for reasons).

### B6. Standard Errors and Clustering

- `cov_type="cluster"` passed to `.fit()` (runner line 270)
- `cov_kwds={"groups": df_prepared["gvkey"].values}` — on same line as cov_type (runner line 270)
- Clustering dimension: entity (gvkey) — firm-clustered standard errors
- SEs apply to the log-odds (logit) coefficients; AME standard errors are computed via the delta method inside `model.get_margeff(at="overall")` (runner line 305)

### B7. Hypothesis Test

- Direction: **one-tailed (beta > 0)** — higher uncertainty predicts more SEC scrutiny
- P-value computation (runner lines 317-319):
  ```python
  ame_p_one = ame_p_two / 2 if ame > 0 else 1 - ame_p_two / 2
  ```
  where `ame_p_two` is the two-tailed p-value from `mfx_df.loc[iv, "Pr(>|z|)"]` (AME distribution)
- Significance thresholds: `***` p < 0.01, `**` p < 0.05, `*` p < 0.10 (runner lines 339-347)
- All four IVs share the same one-tailed direction
- Reported coefficients are Average Marginal Effects (dy/dx), not log-odds

### F1. Dependency Chain

1. **Raw inputs**:
   - `outputs/1.4_AssembleManifest/latest/master_sample_manifest.parquet` (112,968 calls, 2,429 firms, 2002-2018)
   - `inputs/Conference Calls Comment Letters/cccl_conversations_all_years.parquet`

   - `inputs/comp_na_daily_all/comp_na_daily_all.parquet` (Compustat raw data + CIK backup)
   - Stage 2 linguistic outputs: `outputs/2_Textual_Analysis/2.2_Variables/latest/linguistic_variables_{year}.parquet`
   - CRSP daily stock files (via CRSPEngine)

2. **Engine loading** (inside panel builder — H18b reuses the H18 panel, no re-building):
   - `LinguisticEngine`: loads Stage 2 linguistic variables, applies per-year 0%/99% upper-only winsorization to all `_pct` columns (`_linguistic_engine.py` lines 254-259)
   - `CompustatEngine`: loads raw Compustat quarterly data, computes all accounting controls, applies per-fyearq 1%/99% winsorization
   - `CRSPEngine`: loads CRSP daily returns, computes inter-call Volatility

3. **Panel builder** (`build_h18_cccl_received_panel.py`) — H18 and H18b share this step:
   - Loads manifest fields (file_name, gvkey, ff12_code, start_date, ceo_id, ceo_name) via `ManifestFieldsBuilder`
   - Merges 16 builder outputs on `file_name` (sequential left joins; row count must be preserved)
   - Attaches `fyearq` via `attach_fyearq()` (backward merge_asof on gvkey + start_date, requires ≥80% match rate)
   - Converts `fyearq` to numeric as `fyearq_int`
   - Builds CIK-gvkey map from CCM linktable + Compustat direct CIK field (CCM preferred)
   - Creates `CCCL` (forward, Q+1) and `CCCL_lag` (backward, Q-1) binary DVs via calendar-quarter lookup
   - Assigns `sample` column (Main / Finance / Utility) via `assign_industry_sample(ff12_code)`
   - Output: `outputs/variables/h18_cccl_received/{timestamp}/h18_cccl_received_panel.parquet`

4. **Runner loading** (`run_h18b_cccl_logit.py`):
   - Locates panel via `get_latest_output_dir()` using key file `h18_cccl_received_panel.parquet` (runner lines 152-156)
   - Loads panel parquet (runner line 161)
   - Calls `build_cal_yr_qtr_index()` to create `cal_yr`, `cal_qtr`, `cal_yr_qtr` columns (runner line 165)

5. **Sample filtering** (runner lines 170-225, per spec):
   - Filters to main sample: exclude `ff12_code in [8, 11]` (runner line 173)
   - Assigns `Lagged_DV = CCCL_lag` (runner line 191)
   - Builds `required` column list: DV + 4 IVs + controls + `["gvkey", "fyearq_int", "ff12_code"]` (runner line 193)
   - Replaces `inf/-inf` with `NaN` (runner line 199)
   - Drops rows where DV is NaN (runner lines 203-205)
   - Complete-case deletion: drops any row with NaN in any required column (runner lines 207-209)
   - Minimum 5 calls per firm (runner lines 212-216)
   - Casts nullable extension dtypes to float for Patsy compatibility (runner lines 219-222)
   - Casts `cal_yr` to int, `ff12_code` to int (runner lines 222-223)

6. **Regression estimation** (runner `run_logit_regression`, lines 233-335):
   - Builds Patsy formula: `CCCL ~ IV1 + IV2 + IV3 + IV4 + controls + C(ff12_code) + C(cal_yr)`
   - Fits: `smf.logit(formula, data=df).fit(maxiter=300, disp=False, method="bfgs", cov_type="cluster", cov_kwds={"groups": gvkey_array})`
   - Checks convergence via `model.mle_retvals.get("converged", False)`
   - Warns if any FE group has zero CCCL events (runner lines 259-263)
   - Computes AMEs: `model.get_margeff(at="overall")` (runner line 305)
   - Derives one-tailed p-values from AME two-tailed p-values (runner lines 317-319)

7. **Table generation**:
   - H18b has an entry in `outputs/generate_all_tables.py` (see Section I)
   - No separate LaTeX table is written by the runner itself — table generation is handled by `generate_all_tables.py`

## H. OUTLIER AND MISSING DATA TREATMENT
------------------------------------------------------------------------

### H1. Winsorization

**Compustat controls**: 1%/99% per fiscal year (fyearq), applied at CompustatEngine level.
- Applied to: Size, TobinsQ, ROA, BookLev, CapexAt, CashHoldings, RD_Intensity, OCF_Volatility, CashFlow, SalesGrowth
- NOT applied to: DividendPayer (binary)

**Linguistic IVs**: 0%/99% per year (upper-only), applied at LinguisticEngine level (`_linguistic_engine.py` lines 254-259, `winsorize_by_year` with `lower=0.0, upper=0.99`).
- Applied to: CEO_QA_Uncertainty_pct, CEO_Pres_Uncertainty_pct, Manager_QA_Uncertainty_pct, Manager_Pres_Uncertainty_pct
- Rationale: lower bound is 0% by construction; only upper tail clipped

**CCCL DV and CCCL_lag**: Not winsorized (binary 0/1).
**Volatility**: Not winsorized at Compustat engine level (sourced from CRSP engine).

### H2. Missing Data Policy

- Inf/-Inf replaced with NaN before complete-case deletion (runner line 199)
- Complete-case deletion: rows dropped if any required variable is NaN (runner lines 207-209)
- Missing R&D (`xrdq`) treated as zero (CompustatEngine: `xrdq.fillna(0)` before ratio computation)
- Missing debt (`dlcq`, `dlttq`) treated as zero for BookLev (CompustatEngine)
- Patsy drops rows with any NaN in formula variables prior to logit fitting (additional implicit missing data handling)

### H3. Transformations

- Size: natural log of total assets (ln(atq))
- Volatility: annualized (multiply by sqrt(252)) and expressed as percentage (* 100)
- No centering, z-scoring, or other transformations applied to IVs or controls
- Reported coefficients are Average Marginal Effects (dy/dx), not raw log-odds; this transformation is applied post-estimation via `model.get_margeff(at="overall")`

### K3. Logit/Probit/LPM Specifics

**Link function**: Logistic (sigmoid). `smf.logit()` uses the logistic CDF as the link function. This is the nonlinear robustness check for H18's LPM.

**Binary outcome construction**: CCCL ∈ {0, 1}. Construction is identical to H18 LPM: `CCCL = 1` if the firm received any SEC comment letter in calendar quarter Q+1 (the quarter following the call). See Section B2 for full construction detail.

**Separation handling**: The runner explicitly restricts to Industry + Calendar Year FE only to avoid separation (runner docstring lines 19-26):
- Firm FE omitted because ~95% of firms have CCCL=0 for all observations (perfect prediction for those firms under firm-FE logit).
- Year-Quarter FE omitted because 26 of 67 quarters have zero CCCL events (perfect prediction for those quarter dummies).
- Industry FE with 12 categories is feasible; Calendar Year FE with ~16 categories is feasible.
- The runner emits per-FE-group warnings for zero-event groups at runtime (runner lines 259-263).
- Timoneda (2021) is cited as methodological support for this choice.

**Marginal effects computation**: Average Marginal Effects (AMEs) are computed via `model.get_margeff(at="overall")` (runner line 305). This evaluates the marginal effect at each observation and averages, rather than evaluating at the mean of covariates (MEM). The `at="overall"` parameter is the statsmodels default for `get_margeff` and corresponds to AME computation. AMEs from `mfx_df` use columns `dy/dx`, `Std. Err.`, `z`, `Pr(>|z|)`.

**Pseudo-R-squared type**: McFadden's pseudo-R² = `1 - (log-likelihood of fitted model) / (log-likelihood of intercept-only model)`. Accessed via `model.prsquared` (runner line 279). Written to output files as both `R-squared` and `Adj_R2` fields for parse_txt compatibility (runner lines 378-379); the table generator is instructed via `skip_adj_r2: True` to suppress the duplicate row.

**Log-odds vs. AMEs**: The runner computes and stores both:
- Log-odds coefficients and SEs: `model.params.get(iv)` and `model.bse.get(iv)` (runner lines 300-301), stored in `model_diagnostics.csv` as `{iv}_logodds` and `{iv}_logodds_se`
- AMEs (dy/dx) and SEs: `mfx_df.loc[iv, "dy/dx"]` and `mfx_df.loc[iv, "Std. Err."]` (runner lines 309-313), stored as `{iv}_beta` and `{iv}_se`
- The publication table reports AMEs; log-odds are in the output `.txt` files for reference.

**Optimizer**: BFGS (`method="bfgs"`), maximum 300 iterations (`maxiter=300`), no verbose output (`disp=False`). Convergence is checked via `model.mle_retvals.get("converged", False)` (runner line 276); a warning is printed if convergence fails.

## L. KNOWN ISSUES AND NOTES
------------------------------------------------------------------------

1. **Relationship to H18 LPM**: H18b is a robustness check only. The primary specification is H18 (LPM via PanelOLS). H18b confirms whether H18 results hold under a nonlinear model. The restriction to only 2 columns (vs. 6 in H18) is a deliberate methodological constraint, not a limitation of the data.

2. **Pseudo-R² written as both R² and Adj-R²**: The runner writes the same `pseudo_r2` value for both `R-squared` and `Adj_R2` fields in the regression output `.txt` files (runner lines 378-379). This is done for parse_txt compatibility. The table generator is instructed via `skip_adj_r2: True` to suppress the Adj R² row in the publication table, displaying only the Pseudo R² row with label `Pseudo~$R^2$`.

3. **AME standard errors use delta method, not bootstrap**: Statsmodels `get_margeff()` computes SE for AMEs via the delta method (gradient of AME with respect to parameters, applied to the variance-covariance matrix). The VCov is firm-clustered. This is consistent with standard practice but could be bootstrapped for robustness if the delta method approximation is questioned.

4. **Zero-event FE group warnings**: The runner checks for `ff12_code` and `cal_yr` groups with zero CCCL events and prints warnings (runner lines 259-263). These warnings are expected given the 0.3% base rate and do not necessarily cause convergence failure — the binary inclusion variable for the zero-event group simply receives a large negative coefficient with high SE, which is absorbed by statsmodels BFGS.

5. **No report_step4 markdown file**: Unlike many other Stage 4 runners in the pipeline, `run_h18b_cccl_logit.py` does not write a `report_step4_h18b.md` output file. The equivalent information is captured in `model_diagnostics.csv` and `marginal_effects.csv`.

6. **CCCL base rate and separation risk**: At ~0.3% base rate (280 events / 88,205 main-sample calls), the logit likelihood surface may be flat or poorly conditioned even with industry/year FE only. Convergence should be verified by inspecting `model_diagnostics.csv` (field `converged`) after each run. The Timoneda (2021) citation in the docstring is the methodological justification for why LPM is the primary estimator and logit is the robustness check.

7. **Observation counts match H18 LPM exactly**: Col 1 has 57,216 observations (1,615 firms, 200 events); col 2 has 54,915 observations (1,595 firms, 196 events). These match the H18 LPM col 1 and col 3 counts exactly, confirming that Patsy does not additionally drop rows beyond the complete-case + min-calls filter. Source: `outputs/econometric/h18b_cccl_logit/2026-03-31_195228/model_diagnostics.csv`. Note: the event count differs between cols (200 vs 280 in full H18 LPM sample) because the extended-controls filter in col 2 drops some CCCL=1 rows.

8. **Timoneda (2021) citation in reverse**: The runner docstring cites Timoneda (2021) as the reason H18b restricts FE scope. The same paper is cited in H18's docstring as the reason LPM is preferred. Both uses are consistent: Timoneda (2021) argues LPM-FE outperforms logit at <5% base rates, AND that logit with high-dimensional FE creates separation at very low event rates.

9. **Panel reuse across H18 and H18b**: H18b explicitly reuses the H18 panel without rebuilding it (runner docstring lines 7-9 and `load_panel` function lines 143-167). This guarantees identical sample definitions between the LPM and logit analyses. The `--panel-path` CLI argument allows overriding the automatic lookup if needed.
