## B. MODEL SPECIFICATION

### B1. Regression Equation

For each model, the time-varying Cox PH partial likelihood is:

```
h(t | X_{i,t}) = h_0(t) * exp(
    b1 * UncAnsMgr_{i,t}
  + b2 * UncAnsCEO_{i,t}
  + b3 * UncPreMgr_{i,t}
  + b4 * UncPreCEO_{i,t}
  + b5 * lnAssets_{i,t}
  + b6 * BTM_{i,t}
  + b7 * Leverage_{i,t}
  + b8 * ROA_{i,t}
  + b9 * CashRatio_{i,t}
  [+ b10 * SalesGrowth_{i,t} + b11 * FracInt_{i,t} + b12 * dAA_{i,t}]  -- expanded only
)
```

where `t` is in days since 2000-01-01, `h_0(t)` is the baseline hazard (potentially
stratified), and covariates are measured at the earnings call that opens the interval.

Cause-specific hazards replace the event indicator in the partial likelihood:
- Model family All: event = `Takeover` (any bid)
- Model family Uninvited: event = `Takeover_Uninvited` (Hostile + Unsolicited)
- Model family Friendly: event = `Takeover_Friendly` (Friendly + Neutral)

For stratified models, `h_0(t)` is replaced by `h_{0,s}(t)` — a stratum-specific
baseline hazard — where `s` is either calendar year or FF12 industry code.

Source: `run_h9_takeover_hazards.py`, function `run_cox_tv`, lines 382–490; and
`_run_model`, lines 722–803.

### B2. Dependent Variable(s) — Event Indicators

| Variable Name (code) | Description | Construction | Source | Timing |
|----------------------|-------------|--------------|--------|--------|
| `Takeover` | Any takeover bid indicator | 1 only in the call-to-call interval where a bid is announced; 0 in all other intervals of the same firm; 0 for non-target firms | SDC M&A (via TakeoverIndicatorBuilder) | Contemporaneous with interval |
| `Takeover_Uninvited` | Uninvited (Hostile or Unsolicited) bid indicator | `(Takeover == 1) & (Takeover_Type == 'Uninvited')`; other firms treated as censored in this cause-specific model | SDC M&A | Contemporaneous with interval |
| `Takeover_Friendly` | Friendly (Friendly or Neutral) bid indicator | `(Takeover == 1) & (Takeover_Type == 'Friendly')`; other firms treated as censored in this cause-specific model | SDC M&A | Contemporaneous with interval |

**Event definition detail (source: `build_h9_takeover_panel.py` lines 305–315):**
- An interval is marked as an event interval if and only if the takeover announcement
  date falls strictly after the call date and on or before the stop date for that interval.
- Each firm can have at most one event row; validated by assertion at line 362.
- Intervals where takeover event occurs but duration > 1461 days (4 years) are censored
  (`Takeover` forced to 0) — source: lines 331–334.

**Censoring rules:**
- Administrative censoring: `censor_date = {year_end}-12-31` (source: line 261).
- Post-takeover calls: calls on or after the takeover announcement date are removed
  before interval construction (lines 282–291).
- Unknown attitude bids (`Takeover_Type == 'Unknown'`) are censored in both
  cause-specific models — `EVENT_UNINVITED = 0` and `EVENT_FRIENDLY = 0` — which
  is correct competing-risks practice (source: runner lines 282–297, builder lines 339–345).

**Note on Lagged DV:** There is no lagged DV control in Cox PH survival models. The
counting-process format inherently conditions on survival up to the start of each
interval. No Lagged_DV term is present and none is expected for this model family.

### B5. Fixed Effects / Stratification

Cox PH does not use fixed effects in the PanelOLS sense. Instead, the baseline hazard
can be stratified, yielding a stratum-specific `h_{0,s}(t)`.

| Config | Stratification | Column Used | Description |
|--------|---------------|-------------|-------------|
| `sparse` | None (unstratified) | — | Common baseline hazard across all firms |
| `expanded` | None (unstratified) | — | Common baseline hazard across all firms |
| `strata_year` | Year | `year` | Stratum-specific baseline hazard per calendar year |
| `strata_industry` | Industry | `ff12_code` | Stratum-specific baseline hazard per FF12 industry |

Source: `run_h9_takeover_hazards.py`, `_run_model` function lines 722–803;
`run_cox_tv` function lines 423–425 (strata passed to `ctv.fit`).

### B6. Standard Errors

`CoxTimeVaryingFitter` computes the robust sandwich variance estimator internally.
The `lifelines` library's default for `CoxTimeVaryingFitter` uses the observed
information matrix (Fisher information); no additional clustering argument is passed
to `ctv.fit()` in the runner.

Source: `run_h9_takeover_hazards.py` lines 460–470 — `ctv.fit(df_clean, id_col="gvkey",
start_col=START_COL, stop_col=STOP_COL, event_col=event_col, formula=..., strata=strata)`.
No `robust` or `cluster_col` keyword is passed. Diagonal entries of the information
matrix provide the standard errors reported in `ctv.summary`.

### B7. Hypothesis Test

- **Direction:** Two-sided (runner docstring line 27: "two-sided inference").
- **Hypothesis stated:** `beta(Uncertainty) > 0` (higher uncertainty → higher hazard).
- **Inference unit:** Hazard ratio `exp(coef)`. HR > 1 indicates higher hazard (shorter
  survival); HR < 1 indicates lower hazard.
- **P-values:** Two-tailed z-test from `CoxTimeVaryingFitter.summary` column `p`.
  The runner extracts `summary.loc[var, "p"]` directly — no one-tail conversion applied.
  Source: `run_h9_takeover_hazards.py` `extract_results` function line 525.
- **Significance thresholds:** Not explicitly set in the runner; the `lifelines` library
  uses the standard z-distribution for p-values. Standard thresholds apply: *** p<0.01,
  ** p<0.05, * p<0.10.
- **EPV suppression:** Models where Events Per Variable (EPV) < 5 are suppressed from
  the LaTeX table output (`table_hr_rows` filter at line 886). EPV is computed as
  `n_event_firms / n_covariates`. A warning is printed for EPV < 10 (Peduzzi 1995
  minimum recommendation). Source: runner lines 756–764, 886.

## F. DATA PIPELINE

### F1. Dependency Chain

1. **Raw inputs:**
   - `outputs/1.4_AssembleManifest/latest/master_sample_manifest.parquet` — call universe
   - `inputs/comp_na_daily_all/comp_na_daily_all.parquet` — Compustat quarterly
   - `inputs/SDC/sdc-ma-merged.parquet` — SDC M&A deals
   - `outputs/2_Textual_Analysis/2.2_Variables/latest/linguistic_variables_{year}.parquet` — Stage 2 linguistic variables (one file per year)

2. **Engine loading (Stage 3, panel builder):**
   - `LinguisticEngine` — loads all linguistic variable parquets, applies per-year 0%/99% upper winsorization, caches result
   - `CompustatEngine` — loads Compustat quarterly, computes all financial ratios, applies 1%/99% by-year winsorization, caches result
   - `TakeoverIndicatorBuilder` — loads SDC parquet, filters to US public targets in sample period with Completed/Withdrawn/Pending status, links via `cusip6` to manifest gvkeys

3. **Panel builder** (`build_h9_takeover_panel.py`):
   - `build_call_panel`: Loads manifest and merges all builders on `file_name` (left join, row-count-guarded). Assigns `sample` column via `assign_industry_sample(ff12_code)`.
   - `build_call_to_call_panel`: Sorts by `(gvkey, call_date)`. Merges firm-level takeover data on `gvkey`. Removes post-takeover calls. Computes next call date via `.shift(-1)`. Sets `stop_date = min(next_call_date, censor_date)`. If takeover in interval, truncates stop to `Takeover_Date`. Converts to numeric days. Caps long intervals at 1461 days. Creates `Takeover_Uninvited` and `Takeover_Friendly` cause-specific indicators. Removes zero/negative duration rows.
   - Writes: `takeover_panel.parquet`, `summary_stats.csv`, `report_h9_panel.md`, `run_manifest.json`

4. **Runner loading** (`run_h9_takeover_hazards.py`):
   - Loads `takeover_panel.parquet` from `outputs/variables/takeover/latest/`.
   - Validates `ff12_code`, `start`, `stop` columns present.

5. **Sample filtering (runner):**
   - `prepare_main_sample`: drops `ff12_code in [8, 11]` (Finance, Utility).
   - Creates `Takeover_Uninvited` and `Takeover_Friendly` cause-specific indicators in the main sample DataFrame (note: these are also created in the builder; the runner recreates them post-filter with a bug-fix comment at line 270–271).

6. **Regression estimation (runner):**
   - Loops over 4 control configs × 3 event types = 12 calls to `_run_model`.
   - Each call invokes `run_cox_tv`, which calls `CoxTimeVaryingFitter().fit(...)`.
   - Results accumulated in `all_hr_rows` and `diag_rows`.

7. **Table generation:**
   - H9 has **no entry** in `outputs/generate_all_tables.py`. The runner directly calls
     `make_cox_hazard_table` from `f1d.shared.latex_tables_accounting` (line 887) and
     writes `takeover_table.tex` to the timestamped output directory. The standard
     `generate_all_tables.py` workflow does **not** apply to H9.

## H. OUTLIER AND MISSING DATA TREATMENT

### H1. Winsorization

| Variable Group | Level | Applied By |
|---------------|-------|------------|
| Linguistic IVs (`*_pct` columns) | Per-year 0%/99% **upper-only** (lower bound is 0 by construction; only upper tail clipped) | `LinguisticEngine._linguistic_engine.py` lines 235–241 |
| Financial controls (all Compustat variables) | 1%/99% **by calendar year** (symmetric) | `CompustatEngine` at variable computation time |

Source for linguistic winsorization: `_linguistic_engine.py` line 173: "applies per-year
0%/99% winsorization (upper-only)" (docstring confirms asymmetric).
Source for Compustat winsorization: `_compustat_engine.py` MAJOR-6 note line 16.

### H2. Missing Data Policy

- **Complete-case deletion:** Each `run_cox_tv` call drops rows with any NaN in
  `[start, stop, event_col] + covariates`. Source: `run_cox_tv` lines 427–431.
- **No imputation:** No fill, forward-fill, or mean imputation is applied in the runner.
- **`Takeover.fillna(0)` and `Takeover_Type.fillna('None')`:** Applied in the panel
  builder for firms not matched to SDC (source: builder lines 278–279). This is not
  imputation for missing covariates; it is the correct coding for non-target firms.
- **Leverage missing debt components:** `dlcq.fillna(0)` and `dlttq.fillna(0)` applied
  in CompustatEngine (line 948) — missing debt components treated as zero per
  variable spec.

### H3. Transformations

- `lnAssets = ln(atq)` — natural log applied in CompustatEngine (line 943). No further
  transformation in runner.
- No z-scoring, centering, or scaling of any variable in the runner.
- No log-transform of the linguistic IVs in the runner.

**H9 has no entry in `outputs/generate_all_tables.py`.**

Verified by: `grep h9|H9|takeover` on `outputs/generate_all_tables.py` — no matches.

The H9 runner generates its LaTeX table directly via `make_cox_hazard_table` from
`f1d.shared.latex_tables_accounting` (runner line 887). This function writes
`takeover_table.tex` to the timestamped output directory without going through
the centralized `generate_all_tables.py` pipeline.

Reason: H9 uses a non-standard output format (hazard ratios, EPV filtering, no column
numbering) that is incompatible with the `generate_all_tables.py` PanelOLS framework.

### K2. Cox Proportional Hazards Specifics

**Time origin and time scale:**
- Reference date: `2000-01-01` (constant `REFERENCE_DATE` in builder, line 94).
- Time units: days since 2000-01-01 (integer).
- `start_col = "start"`, `stop_col = "stop"` in counting-process format.
- Source: builder lines 317–318; runner constants lines 184–185.

**Duration construction (start/stop):**
- `start = (call_date - 2000-01-01).days`
- `stop = min(next_call_date, censor_date)` then truncated to `Takeover_Date` if event
  falls within interval, then capped at `start + 1461`.
- `next_call_date` computed as `df.groupby("gvkey")["call_date"].shift(-1)`.
- Final last call for a firm: `stop = censor_date` (or `Takeover_Date` if targeted).
- Source: builder `build_call_to_call_panel` lines 296–337.

**Event definition:**
- Event indicator = 1 only when `Takeover_Date > call_date AND Takeover_Date <= stop_date` (original stop before truncation).
- Source: builder lines 305–314 (`tk_in_interval` mask and `df["Takeover"] = tk_in_interval.astype(int)`).

**Censoring rules:**
- Administrative censoring: `censor_date = {year_end}-12-31`; source: builder line 261.
- Post-takeover calls excluded (not censored; removed entirely): builder lines 282–291.
- Competing events of unknown attitude (`Takeover_Type == 'Unknown'`): censored
  in both cause-specific models (event indicators = 0 for those intervals).
- Long event intervals (> 1461 days): censored (`Takeover → 0`); source builder
  lines 331–334.

**Risk set:**
- Counting-process (start-stop intervals) — allows time-varying covariates where
  each row's covariates are measured at the call that opens the interval.
- One row per call per at-risk firm.
- Subject identifier: `gvkey` passed as `id_col="gvkey"` to `ctv.fit`.

**Ties method:**
- `CoxTimeVaryingFitter` in lifelines uses Efron's method by default. No
  explicit `ties` argument is passed in the runner. Source: runner line 461–470.
  [UNVERIFIED: the specific lifelines version's default ties method — Efron is standard
  in lifelines but the installed version was not checked in the runner code.]

**Strata variables:**
- `strata_year` models: `strata="year"` — year is the calendar year of the call
  opening the interval, extracted as `pd.to_datetime(start_date).dt.year`.
- `strata_industry` models: `strata="ff12_code"` — Fama-French 12 industry code
  from the manifest.
- Strata sparsity diagnostic: printed for strata with < 5 events; source runner
  lines 452–458.
- Source: runner `_run_model` lines 838–858 passing `strata="year"` and
  `strata="ff12_code"`.

**Concordance index computation:**
- Computed via `compute_concordance_time_varying` (runner lines 307–379).
- Approach: predict mean partial hazard per subject across all intervals; use last
  observation's stop time and event indicator; compute Harrell's C-index via
  `lifelines.utils.concordance_index`.
- Reported in `.txt` output files and `model_diagnostics.csv`.

**Events Per Variable (EPV):**
- `EPV = n_event_firms / n_covariates`
- With 4 IVs + 5 sparse controls = 9 covariates, EPV is lower than single-IV designs.
- Warning threshold: EPV < 10 (Peduzzi 1995 recommendation).
- Critical threshold: EPV < 5 → model suppressed from LaTeX table output.
- Source: runner lines 756–764, 886.

**Competing risks approach:**
- Cause-specific hazards (not Fine-Gray subdistribution hazards).
- Competing events are simply censored in each cause-specific model.
- Uninvited and Friendly models treat each other and Unknown bids as censoring.
- Source: runner docstring line 51: "Unknown types are correctly censored in cause-specific models."

## L. KNOWN ISSUES AND NOTES

1. **Unused variables in panel:** `AnalystQAUncertaintyBuilder` and
   `NegativeSentimentBuilder` are built into the panel parquet (builder lines 151–156)
   but neither variable appears in any regression specification in the runner.
   They consume memory and build time without contributing to estimates.
   Source: builder `builders` dict lines 151–156 vs runner `KEY_IVS` line 176–181.

2. **Duplicate cause-specific indicator creation:** `Takeover_Uninvited` and
   `Takeover_Friendly` are created both in the panel builder (`build_call_to_call_panel`
   lines 339–345) and again in the runner's `prepare_main_sample` (lines 273–274).
   The runner comment at line 270 marks the builder version as a "BUG FIX (Pass 03)"
   and the runner recreates them post-filter. The panel parquet version may not be used.
   This is not a correctness bug (the runner's version is what governs regressions)
   but is an inconsistency to be aware of.

3. **`generate_all_tables.py` not integrated:** H9 is the only survival suite and
   generates its own LaTeX table via `make_cox_hazard_table`. If `generate_all_tables.py`
   is run to regenerate tables for all suites, H9 results will not be updated.
   The H9 table must be regenerated by re-running the runner directly.

4. **Ties method unverified:** The specific ties handling method used by the installed
   version of `lifelines.CoxTimeVaryingFitter` was not inspected. Standard lifelines
   uses Efron's method but this was not confirmed in the runner code. Marked
   [UNVERIFIED] in K2.

5. **SE computation — no explicit clustering:** The runner does not pass a `cluster_col`
   argument to `ctv.fit()`. Lifelines' `CoxTimeVaryingFitter` computes standard errors
   from the Fisher information matrix. Whether the `id_col="gvkey"` argument induces
   any within-subject variance correction should be verified against the lifelines
   documentation for the installed version.

6. **EPV concern for Uninvited models:** The runner report (lines 587–590) explicitly
   notes: "With 4 IVs per model, EPV will be lower than single-IV designs. Models with
   EPV < 5 (Peduzzi 1995) are suppressed from the LaTeX table. Uninvited expanded models
   are most likely to fall below this threshold." This means some models may not appear
   in the published table, depending on runtime event counts.

7. **Docstring vs code — hypothesis direction:** The old H9 docstring referred to
   `beta(Clarity) < 0` and `ClarityCEO` as IV. The current runner (as of 2026-04-01)
   states `beta(Uncertainty) > 0` with the 4 standard uncertainty IVs. The code is
   the source of truth; this provenance document reflects the current code.

8. **CUSIP6 ambiguity:** `TakeoverIndicatorBuilder` logs a warning if any CUSIP6 maps
   to multiple gvkeys. Such ambiguity introduces measurement error in the Takeover
   indicator, biasing estimates toward null. Source: `takeover_indicator.py` lines
   93–98.
