## B. MODEL SPECIFICATION

### B1. Regression Equation

The Cox proportional hazards model with time-varying covariates is:

$$
h_i(t \mid \mathbf{X}_i(t)) = h_0(t) \cdot \exp\bigl(\beta_1 \cdot \text{Clarity}_{i,t} + \boldsymbol{\gamma} \cdot \mathbf{Controls}_{i,t}\bigr)
$$

where $h_0(t)$ is the unspecified baseline hazard, $\text{Clarity}_{i,t}$ is one of three clarity constructs (ClarityCEO, CEO_Clarity_Residual, or Manager_Clarity_Residual) measured at the call opening interval $t$, and $\mathbf{Controls}_{i,t}$ are financial covariates measured at the same call date.

Time is measured in days since 2000-01-01. Each observation is a call-to-call interval in counting-process (start, stop] format. Covariates are constant within each interval and update at the next earnings call.

For stratified models, the baseline hazard is allowed to vary across strata:

$$
h_i(t \mid \mathbf{X}_i(t)) = h_{0,s}(t) \cdot \exp\bigl(\beta_1 \cdot \text{Clarity}_{i,t} + \boldsymbol{\gamma} \cdot \mathbf{Controls}_{i,t}\bigr)
$$

where $s$ indexes strata (year or FF12 industry).

*Source: run_h9_takeover_hazards.py, lines 396--504 (run_cox_tv function); lifelines.CoxTimeVaryingFitter.fit() call at lines 475--484.*

### B5. Fixed Effects / Stratification / Random Effects

Cox PH does not use absorbed fixed effects. Instead, the baseline hazard can be stratified:

| Configuration | Strata Variable | Description |
|---|---|---|
| Unstratified (sparse) | None | Single baseline hazard h_0(t) for all firms |
| Unstratified (expanded) | None | Same, with expanded control block |
| Year-stratified | `year` | Separate baseline hazard per calendar year |
| Industry-stratified | `ff12_code` | Separate baseline hazard per Fama-French 12 industry |

Stratification allows the baseline hazard to differ across groups without estimating group-specific coefficients (analogous to stratified Cox in epidemiology). Coefficients are assumed common across strata.

*Source: run_h9_takeover_hazards.py lines 865-893 (year-stratified and industry-stratified blocks).*

### B6. Standard Errors and Clustering

lifelines.CoxTimeVaryingFitter uses the **standard variance estimator** (inverse information matrix) by default. The constructor is called with no arguments (line 475: `CoxTimeVaryingFitter()`), and no `robust=True` parameter is passed to `fit()` (lines 476-484). The `id_col="gvkey"` parameter identifies subjects for the partial likelihood; it does NOT activate robust/sandwich standard errors. To obtain robust SEs in lifelines, `robust=True` must be explicitly passed to `CoxTimeVaryingFitter(robust=True)`. Standard (non-robust) SEs are used in this suite.

*Source: run_h9_takeover_hazards.py lines 475-484.*

### B7. Hypothesis Test

- **Direction:** Two-sided inference (runner docstring line 27: "Hypothesis Tests (two-sided inference):")
- **P-values:** lifelines reports two-sided p-values by default from the Wald z-test (coef / se(coef))
- **Significance thresholds:** Standard *** p<0.01, ** p<0.05, * p<0.10
- **Hazard ratio interpretation:**
  - HR < 1 (exp(coef) < 1): lower hazard, longer expected survival (lower takeover likelihood)
  - HR > 1 (exp(coef) > 1): higher hazard, shorter expected survival (higher takeover likelihood)
- **H9-A test:** beta(Clarity) < 0 implies HR < 1, meaning clearer CEOs have lower takeover hazard
- **H9-B evaluation:** Descriptive comparison of point estimates in uninvited vs. friendly cause-specific models. No formal cross-model test is conducted due to limited uninvited events (EPV < 10)

*Source: run_h9_takeover_hazards.py lines 27-29 (docstring), lines 507-551 (extract_results), lines 602-606 (report H9-B note).*

   - Build call-level panel from manifest + all builders (left joins on file_name)
   - Merge ClarityCEO scores (left join on ceo_id + sample)
   - Load firm-level takeover indicators from SDC (TakeoverIndicatorBuilder)
   - Construct call-to-call counting-process intervals (build_call_to_call_panel)

   - Load `takeover_panel.parquet` from latest variables/takeover/ directory
   - Filter to Main sample (exclude FF12 codes 8 and 11)
   - Recreate cause-specific indicators (Takeover_Uninvited, Takeover_Friendly) with BUG FIX from Pass 03

5. **Sample filtering:**
   - FF12 exclusion (Finance, Utility)
   - Complete-case deletion per model (dropna on start, stop, event_col, and all covariates)
   - Minimum 50 observations and minimum 5 event firms to fit

6. **Regression estimation:**
   - CoxTimeVaryingFitter.fit() with id_col="gvkey", start_col="start", stop_col="stop"
   - Output: per-model .txt files, hazard_ratios.csv, model_diagnostics.csv

7. **Table generation:**

### K2. Cox Proportional Hazards Specifics

**Time origin and time scale:**
- Reference date: 2000-01-01 (REFERENCE_DATE, panel builder line 98)
- Time units: integer days since 2000-01-01
- Start column: `start` = (call_date - 2000-01-01).days
- Stop column: `stop` = (min(next_call_date, takeover_date, censor_date) - 2000-01-01).days

**Duration construction (counting-process intervals):**
- Each interval opens at an earnings call date and closes at the earliest of:
  (a) the next earnings call date for the same firm
  (b) the takeover announcement date (if the bid falls in the interval)
  (c) the administrative censor date (2018-12-31)
- Intervals are (start, stop] -- left-open, right-closed
- `start` and `stop` are integer day counts passed to CoxTimeVaryingFitter
- Covariates are measured at the call that opens the interval and held constant within the interval

*Source: build_h9_takeover_panel.py lines 256-416 (build_call_to_call_panel).*

**Event definition:**
- `Takeover = 1` only in the single interval where the first bid announcement date falls in (call_date, stop_date]
- Each firm has at most 1 event row (validated at build_h9_takeover_panel.py lines 383-391)
- For cause-specific models:
  - `Takeover_Uninvited = 1` if event AND Takeover_Type == 'Uninvited'
  - `Takeover_Friendly = 1` if event AND Takeover_Type == 'Friendly'
  - Events with 'Unknown' Takeover_Type are censored (0) in both cause-specific models (correct competing-risks treatment, documented at runner lines 297-311)

**Censoring rules:**
1. Administrative censoring: all intervals are capped at 2018-12-31 (panel builder line 283, 324)
2. Interval cap: intervals exceeding 1,461 days (4 years) are capped at start + 1,461 days. If an event falls beyond the cap, it is censored (Takeover set to 0) to prevent phantom events (panel builder lines 343-359)
3. Post-takeover calls: calls occurring on or after the takeover date are removed from the risk set entirely (panel builder lines 304-316)
4. Right-censoring: firms that never receive a bid are censored at their last observed interval stop time

**Risk set: Start-stop intervals (counting-process format):**
- One row per call-to-call interval per firm (NOT one row per subject)
- Multiple rows per firm with time-varying covariates that update at each call
- CoxTimeVaryingFitter handles the counting-process likelihood correctly
- Subject identification: `id_col="gvkey"` (runner line 479)

**Ties method:**
- lifelines CoxTimeVaryingFitter uses Efron's method by default for handling tied event times
- No explicit ties parameter is set in the code

**Strata variables (stratified baseline hazard):**
- Unstratified: single baseline hazard for all firms (default)
- Year-stratified: `strata="year"` -- separate h_0(t) per calendar year (runner line 877)
- Industry-stratified: `strata="ff12_code"` -- separate h_0(t) per FF12 industry (runner line 892)
- Strata sparsity diagnostic: warning logged if any stratum has < 5 events (runner lines 466-472)

**Concordance index computation:**
- CoxTimeVaryingFitter does not expose concordance_index_ directly
- Custom computation in `compute_concordance_time_varying()` (runner lines 321-393):
  1. Predict partial hazard for all observations
  2. Compute mean partial hazard per subject (gvkey) across all intervals
  3. Take last observation per subject for event time and indicator
  4. Compute Harrell's C-index via `lifelines.utils.concordance_index()`
- Requires minimum 10 subjects with non-NaN values (line 378)
- Returns None on any exception (line 392)

**Events Per Variable (EPV) and suppression rules:**
- EPV = N_event_firms / N_covariates (runner lines 784-785)
- EPV thresholds (runner lines 787-791):
  - EPV >= 10: "ok" -- standard minimum per Peduzzi et al. (1995)
  - 5 <= EPV < 10: "low" -- below recommended minimum, results reported with caveat
  - EPV < 5: "critical" -- results suppressed from LaTeX table (runner line 919)
- EPV computed per model (event-type x variant x control-block combination)

**Competing risks approach:**
- Cause-specific hazard approach: separate Cox models for each event type
- In cause-specific models, events of other types are treated as censored:
  - Uninvited model: Friendly and Unknown events are censored (Takeover_Uninvited = 0)
  - Friendly model: Uninvited and Unknown events are censored (Takeover_Friendly = 0)
- This is standard cause-specific competing risks (NOT Fine-Gray subdistribution hazard)
- 26 events with 'Unknown' Takeover_Type are censored in both cause-specific models (run_log.txt line 22)

*Source: run_h9_takeover_hazards.py lines 321-393 (concordance), 475-484 (fit call), 783-791 (EPV), 918-919 (suppression); build_h9_takeover_panel.py lines 283-416.*

## L. KNOWN ISSUES AND NOTES

1. **ClarityCEO 0% coverage (BLOCKING):** All CEO variant models (12 of 36 attempted) fail with "Insufficient observations for regression: 0. Minimum required: 50." ClarityCEO has zero non-missing values after complete-case deletion. This is documented as a known blocker. Only the two residual variants (CEO_Clarity_Residual, Manager_Clarity_Residual) produce fitted models.

2. **Structurally different sub-samples across variants:** The three clarity variants operate on different complete-case samples (CEO: 0 obs, CEO_Residual: 36,860 intervals from 1,272 firms, Manager_Residual: 50,628 intervals from 1,488 firms). Cross-variant coefficient differences reflect both construct differences and sample composition differences. The runner explicitly notes this in RT-3 (lines 607-611).

3. **Low EPV in cause-specific models:** Uninvited event counts are small (24 events for CEO_Residual, 33 for Manager_Residual with sparse controls). EPV ranges from 4.0 (critical) to 5.5 (low). Models with EPV < 5 are suppressed from the LaTeX table. Even "low" EPV models should be interpreted with caution per Peduzzi et al. (1995).

4. **Concordance index near 0.5:** Most models have concordance index near 0.50 (random prediction), indicating limited discriminative ability of the included covariates for predicting takeover events. The highest concordance is 0.52 (Manager_Residual expanded All-takeover model).

5. **Panel builder loads linguistic variables not used in Cox models:** The panel builder imports and merges Manager_QA_Uncertainty_pct, CEO_QA_Uncertainty_pct, Analyst_QA_Uncertainty_pct, and Entire_All_Negative_pct via their respective builders. These appear in the takeover_panel.parquet columns but are NOT used as covariates in any Cox model. They exist in the panel for potential future analysis.

6. **BUG FIX documented in runner (Pass 03):** The runner recreates Takeover_Uninvited and Takeover_Friendly from Takeover + Takeover_Type at lines 287-288, noting that previous code "marked ALL intervals of firms with that takeover type as events, inflating cause-specific event counts by ~8-9x." This is correctly fixed.

7. **CUSIP6 ambiguity in SDC linkage:** The TakeoverIndicatorBuilder warns if a single CUSIP6 maps to multiple gvkeys (potential false positive takeover assignments). This diagnostic is logged at builder runtime (takeover_indicator.py lines 92-98). The direction of bias is toward the null (false positive events dilute the true effect).

8. **No formal H9-B test:** H9-B (comparing uninvited vs. friendly clarity coefficients) is evaluated descriptively, not with a formal cross-model test. The runner documents this limitation at lines 602-606.

9. **No ClarityManager construct:** The docstring and code explicitly note that ClarityManager (a Manager-level fixed-effect clarity score) does not exist in the repository. Only ClarityCEO exists as a fixed-effect score; Manager variants are available only as residuals.

10. **Administrative censor date is hard-coded:** The censor date is derived from `year_end` which comes from `config.data.year_end` (project.yaml). Currently 2018-12-31.

11. **Docstring/code mismatch on output filename:** The runner docstring (line 64) lists the output as `takeover_hazard_table.tex`, but the code actually writes `takeover_table.tex` (line 940). The code is truth; the docstring is stale.
