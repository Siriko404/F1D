## B. MODEL SPECIFICATION

### B1. Regression Equation

**Contemporaneous (cols 1-6):**

$$\text{PayoutRatio\_q}_{i,t} = \beta_1 \cdot \text{CEO\_QA\_Uncertainty\_pct} + \beta_2 \cdot \text{CEO\_Pres\_Uncertainty\_pct} + \beta_3 \cdot \text{Manager\_QA\_Uncertainty\_pct} + \beta_4 \cdot \text{Manager\_Pres\_Uncertainty\_pct} + \gamma' \mathbf{Controls} + \alpha_i + \delta_t + \varepsilon_{i,t}$$

**Lead (cols 7-12):**

$$\text{PayoutRatio\_q\_lead\_qtr}_{i,t} = \beta_1 \cdot \text{CEO\_QA\_Uncertainty\_pct} + \beta_2 \cdot \text{CEO\_Pres\_Uncertainty\_pct} + \beta_3 \cdot \text{Manager\_QA\_Uncertainty\_pct} + \beta_4 \cdot \text{Manager\_Pres\_Uncertainty\_pct} + \gamma' \mathbf{Controls} + \alpha_i + \delta_t + \varepsilon_{i,t}$$

Where $\alpha_i$ is entity FE (Industry FF12 or Firm) and $\delta_t$ is time FE (Calendar Year or Calendar Year-Quarter).

### B2. Dependent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| PayoutRatio_q | Quarterly payout ratio | (dvpspq x cshoq) / ibq; NaN when ibq <= 0; dvpspq NaN with ibq > 0 treated as 0 | CompustatEngine: dvpspq, cshoq, ibq | Contemporaneous (t) |
| PayoutRatio_q_lead_qtr | Next fiscal quarter's payout ratio | PayoutRatio_q shifted forward one consecutive fiscal quarter within gvkey | CompustatEngine (derived) | Lead (t+1 quarter) |

**PayoutRatio_q construction detail** (verified at `_compustat_engine.py` lines 1014-1023):
1. `quarterly_div = dvpspq.fillna(0) * cshoq` -- missing dividends treated as zero
2. `PayoutRatio_q = quarterly_div / ibq` when `ibq > 0`; NaN otherwise
3. dvpspq is a true quarterly field (single-quarter, not YTD cumulative)

**PayoutRatio_q_lead_qtr construction detail** (verified at `build_h12_payout_panel.py` lines 160-276):
1. Build firm-quarter lookup: for each (gvkey, fiscal_qtr_id), take PayoutRatio_q from the call with latest start_date
2. `fiscal_qtr_id = fyearq_int * 10 + fqtr_int` (e.g., 20103 = FY2010 Q3)
3. Shift PayoutRatio_q forward by one quarter within gvkey
4. Consecutiveness check: next quarter must be current + 1 (within year) or Q1 of next fiscal year (if current is Q4)
5. Non-consecutive gaps produce NaN (no stale carry-forward)
6. Merge lead values back to call level on (gvkey, fiscal_qtr_id)

### B7. Hypothesis Test

- **Direction**: One-tailed (beta < 0) -- higher uncertainty predicts lower payout
- **P-value computation** (verified at runner lines 326-329):
  ```python
  if beta < 0:
      p_one = p_two / 2
  else:
      p_one = 1 - p_two / 2
  ```
- **Significance thresholds** (runner lines 342-351):
  - `***` p < 0.01
  - `**` p < 0.05
  - `*` p < 0.10
- All four IVs tested with the same one-tailed direction (beta < 0)

## F. DATA PIPELINE

### F1. Dependency Chain

1. **Raw inputs**:
   - `outputs/1.4_AssembleManifest/latest/master_sample_manifest.parquet` (112,968 calls)
   - Compustat quarterly data (raw SAS/parquet via CompustatEngine)
   - CRSP daily stock returns (via CRSPEngine)
   - Stage 2 linguistic variables: `outputs/2_Textual_Analysis/2.2_Variables/latest/linguistic_variables_{year}.parquet`

   - CompustatEngine: loads raw Compustat, computes PayoutRatio_q, lnAssets, Leverage, TobinsQ, ROA, CashRatio, Capex, sCFO, SalesGrowth, RDSales, CashFlowAt; winsorizes 1%/99% by fiscal year
   - CRSPEngine: loads daily returns, computes DailyVola; winsorizes 1%/99% per year
   - LinguisticEngine: loads Stage 2 linguistic parquets, winsorizes 0%/99% upper-only per year

3. **Panel builder** (`build_h12_payout_panel.py`):
   - Load manifest fields (file_name, gvkey, ff12_code, start_date, etc.)
   - Merge all builder outputs on file_name (left join)
   - Create lead/lag variables using fiscal quarter shifting with consecutiveness checks
   - Assign industry sample labels
   - Output: `h12_payout_panel.parquet`

4. **Runner loading** (`run_h12_payout.py`):
   - Load panel parquet from `outputs/variables/h12_payout/latest/`
   - Build cal_yr_qtr index via `build_cal_yr_qtr_index()`

5. **Sample filtering** (per-spec in `prepare_regression_data()`):
   - Filter to main sample (FF12 != 8, 11)
   - Create Lagged_DV from `PayoutRatio_q_lag`
   - Replace inf/-inf with NaN
   - Drop DV-null rows (includes ibq <= 0 cases)
   - Complete-case deletion on all required columns
   - Min 5 calls per firm filter

6. **Regression estimation**:
   - PanelOLS with firm-clustered SEs
   - 12 model specifications (see Section C)
   - One-tailed p-values computed post-estimation

## H. OUTLIER AND MISSING DATA TREATMENT

### H1. Winsorization

**Compustat variables** (via `_winsorize_by_year` in `_compustat_engine.py` lines 444-468):
- **Level**: 1%/99% per fiscal year (fyearq), symmetric
- **Min obs threshold**: 10 observations per year group
- **Applied to**: lnAssets, Leverage, TobinsQ, ROA, CashRatio, Capex, PayoutRatio_q, sCFO, RDSales, EPSgrowth, and all other COMPUSTAT_COLS except DivDummy, CashFlowAt, SalesGrowth, fqtr
- **CashFlowAt, SalesGrowth**: Winsorized 1%/99% per fiscal year inside `_compute_biddle_residual()` (not double-winsorized)
- **DivDummy**: Binary, not winsorized
- **fqtr**: Identifier, not winsorized

**Linguistic IVs** (via `winsorize_by_year` in `_linguistic_engine.py` lines 255-258):
- **Level**: 0%/99% per year (upper-only), using start_date year
- **Min obs threshold**: 10 observations per year group
- **Applied to**: All _pct columns including the four uncertainty IVs
- **Rationale**: Bounded [0, 100] by construction; only upper tail needs trimming

**CRSP variables** (via `winsorize_by_year` in `_crsp_engine.py` lines 445-447):
- **Level**: 1%/99% per year
- **Applied to**: DailyVola

### H2. Missing Data Policy

- **Complete-case deletion**: Rows dropped if any required variable is NaN (runner line 231-232)
- **Inf/-Inf replacement**: Replaced with NaN before regression (runner line 223)
- **Negative earnings filter**: ibq <= 0 produces NaN PayoutRatio_q (explicit exclusion at engine level)
- **Missing dividends**: dvpspq NaN with ibq > 0 treated as zero dividends (PayoutRatio_q = 0)
- **Non-consecutive fiscal quarters**: Lead and lag values set to NaN for gaps

| Variable | Transformation |
|----------|---------------|
| lnAssets | Natural logarithm of atq |
| DailyVola | Annualized: std(daily_ret) x sqrt(252) x 100 |
| sCFO | Rolling 5-year std of annual OCF/assets ratio |

No centering, z-scoring, or scaling applied to any IV or DV.

## L. KNOWN ISSUES AND NOTES

1. **Zero-inflation in DV**: Approximately 57% of main-sample firm-quarters with ibq > 0 have PayoutRatio_q = 0 (no dividend paid that quarter). This "dividend lumpiness" means the DV has a large mass point at zero. The suite uses continuous OLS with PanelOLS rather than a Tobit, hurdle, or zero-inflated model. Documented explicitly in the runner docstring (line 37-38) and LaTeX table notes.

2. **Output filename inconsistency**: The current runner code (line 496) writes `h12_payout_table.tex`, but the actual latest run output on disk (2026-03-27_095009) has `h12q_payout_table.tex`. This indicates the latest run was produced by an earlier version of the runner with a different filename. Similarly, the panel builder output parquet on disk is named `h12q_payout_panel.parquet` while the current code writes `h12_payout_panel.parquet`.

3. **R-squared interpretation**: Firm FE specifications (even columns) show near-zero or slightly negative adjusted R-squared values (e.g., col 2: adj_R2 = -0.023). This is expected for within-R-squared in firm FE models when between-firm variation dominates and idiosyncratic within-firm variation in payout ratios is largely noise. The R-squared reported by PanelOLS in these specs is the overall (not within) R-squared.

4. **Negative earnings exclusion**: The ibq <= 0 filter drops 17,510 calls from the main sample (24.8% of 70,695 main-sample calls with valid DV). This is a design choice -- payout ratios are undefined or misleading for firms with non-positive quarterly earnings. The DV is thus conditioned on profitability.

5. **Lagged_DV always present**: Lagged_DV (PayoutRatio_q_lag) is included in BASE_CONTROLS, so it appears in all 12 specifications. For lead specs (cols 7-12), this means the model includes the previous quarter's actual payout ratio as a control when predicting the next quarter's payout ratio.

6. **cal_yearqtr vs cal_yr_qtr**: The panel builder creates a `cal_yearqtr` column (line 306-308), while the runner creates `cal_yr_qtr` via `build_cal_yr_qtr_index()` (called at runner line 182). Both use `year * 10 + quarter` from start_date, so they are functionally identical. The runner's version is what actually enters the regression.
