Title:           Speech Uncertainty and Post-Call Illiquidity

## B. MODEL SPECIFICATION
------------------------------------------------------------------------

### B1. Regression Equation

$$\Delta\text{Amihud}_{i,t} = \beta_1 \text{CEO\_QA\_Unc} + \beta_2 \text{CEO\_Pres\_Unc} + \beta_3 \text{Mgr\_QA\_Unc} + \beta_4 \text{Mgr\_Pres\_Unc} + \gamma' \mathbf{Controls} + \alpha_i + \delta_t + \varepsilon_{i,t}$$

Where $\alpha_i$ is entity FE (Industry FF12 or Firm) and $\delta_t$ is time FE (Calendar Year or Calendar Year-Quarter), depending on specification.

### B2. Dependent Variable(s)

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| `delta_amihud` | Change in Amihud illiquidity around call | PostAmihud - PreAmihud, where daily_illiq_d = \|RET_d\| / (VOL_d * \|PRC_d\|) * 1e6; PreAmihud = mean(daily_illiq for trading days [-3,-1] relative to call ref date); PostAmihud = mean(daily_illiq for trading days [+1,+3] relative to call ref date) | CRSPEngine: RET, VOL, PRC via `get_raw_daily_data()` | Event-window: pre [-3,-1] vs post [+1,+3] trading days around call |

### B3. Independent Variable(s)

All 4 IVs enter simultaneously in every specification.

| Variable Name (code) | Description | Formula | Source Engine | Timing |
|---|---|---|---|---|
| `CEO_QA_Uncertainty_pct` | CEO Q&A uncertainty percentage | Percentage of CEO words in Q&A section classified as uncertainty by Loughran-McDonald dictionary | LinguisticEngine (Stage 2 textual analysis) | Contemporaneous (call date) |
| `CEO_Pres_Uncertainty_pct` | CEO presentation uncertainty percentage | Percentage of CEO words in Presentation section classified as uncertainty | LinguisticEngine (Stage 2 textual analysis) | Contemporaneous (call date) |
| `Manager_QA_Uncertainty_pct` | Manager (all mgmt) Q&A uncertainty percentage | Percentage of all management words in Q&A section classified as uncertainty | LinguisticEngine (Stage 2 textual analysis) | Contemporaneous (call date) |
| `Manager_Pres_Uncertainty_pct` | Manager (all mgmt) presentation uncertainty percentage | Percentage of all management words in Presentation section classified as uncertainty | LinguisticEngine (Stage 2 textual analysis) | Contemporaneous (call date) |

### B4. Control Variables

**Base Controls (8 variables):**

| Variable Name (code) | Description | Formula | Source Engine |
|---|---|---|---|
| `Size` | Firm size | ln(atq), atq > 0 only | CompustatEngine: atq |
| `TobinsQ` | Tobin's Q | (cshoq * prccq + dlcq + dlttq) / atq | CompustatEngine: cshoq, prccq, dlcq, dlttq, atq |
| `ROA` | Return on assets | iby_annual (Q4) / avg_assets, where avg_assets = (atq_t + atq_{t-1}) / 2 | CompustatEngine: iby, atq |
| `BookLev` | Book leverage | (dlcq + dlttq) / atq; missing debt treated as 0 | CompustatEngine: dlcq, dlttq, atq |
| `CapexAt` | Capital expenditure intensity | capxy_annual (Q4 only) / atq_lag | CompustatEngine: capxy, atq |
| `DividendPayer` | Dividend payer indicator | 1 if dvy_annual (Q4 only) > 0, else 0 | CompustatEngine: dvy |
| `OCF_Volatility` | Operating cash flow volatility | Rolling 5-year std (min 3 yrs) of (oancfy / atq_{t-1}) per gvkey | CompustatEngine: oancfy, atq |
| `pre_call_amihud` | Pre-call Amihud illiquidity level | mean(daily_illiq for trading days [-3,-1]) where daily_illiq = \|RET\| / (VOL * \|PRC\|) * 1e6 | CRSPEngine: RET, VOL, PRC |

Note: `pre_call_amihud` serves as the Lagged DV / pre-event level control, capturing the baseline illiquidity level before the call.

**Extended Controls (Base + 4 additional):**

| Variable Name (code) | Description | Formula | Source Engine |
|---|---|---|---|
| `Volatility` | Stock return volatility | std(daily RET) * sqrt(252) * 100, over inter-call window [current_call+1d, next_call-5d], min 10 trading days | CRSPEngine: RET via `get_data()` |
| `StockPrice` | Stock price at call date | PRC at call date (or nearest prior trading day) | CRSPEngine: PRC via `get_raw_daily_data()` |
| `Turnover` | Share turnover at call date | VOL / (SHROUT * 1000) at call date (or nearest prior trading day) | CRSPEngine: VOL, SHROUT via `get_raw_daily_data()` |
| `Analyst_QA_Uncertainty_pct` | Analyst Q&A uncertainty percentage | Percentage of analyst words in Q&A section classified as uncertainty | LinguisticEngine (Stage 2 textual analysis) |

### B5. Fixed Effects

| FE Type | Column Used | Description | Specs |
|---|---|---|---|
| Industry | `ff12_code` | Fama-French 12 industry classification, absorbed via PanelOLS `other_effects` | Cols 1, 3, 5 |
| Firm (Entity) | `gvkey` | Firm fixed effects, absorbed via PanelOLS `EntityEffects` | Cols 2, 4, 6 |
| Calendar Year | `cal_yr` | Calendar year (from `start_date.dt.year`), absorbed via PanelOLS `time_effects=True` | Cols 1, 2, 3, 4 |
| Calendar Year-Quarter | `cal_yr_qtr` | Calendar year-quarter (year*10 + quarter from `start_date`), absorbed via PanelOLS `time_effects=True` | Cols 5, 6 |

### B6. Standard Errors and Clustering

- **cov_type**: `"clustered"`
- **Clustering dimension**: Entity (`cluster_entity=True`) -- clusters at firm (gvkey) level
- **Small-sample corrections**: Default PanelOLS clustered SE corrections

Source: `run_h7_illiquidity.py` lines 250, 255.

### B7. Hypothesis Test

- **Direction**: one-tailed (beta > 0) -- higher uncertainty implies more illiquidity
- **P-value computation**: `p_one = p_two / 2 if beta > 0 else 1 - p_two / 2` (runner line 279)
- **Significance thresholds**: `***` p < 0.01, `**` p < 0.05, `*` p < 0.10
- **Applied to**: All 4 IV coefficients in each specification

## F. DATA PIPELINE
------------------------------------------------------------------------

### F1. Dependency Chain

1. **Raw inputs**:
   - `inputs/CRSP_DSF/CRSP_DSF_{year}_Q{1-4}.parquet` -- CRSP daily stock files
   - `inputs/comp_na_daily_all/comp_na_daily_all.parquet` -- Compustat quarterly fundamentals
   - `inputs/CRSPCompustat_CCM/CRSPCompustat_CCM.parquet` -- CRSP-Compustat link table
   - `outputs/2_Textual_Analysis/2.2_Variables/latest/linguistic_variables_{year}.parquet` -- Stage 2 linguistic measures
   - `outputs/1.4_AssembleManifest/latest/master_sample_manifest.parquet` -- call-level manifest

2. **Engine loading**:
   - **CompustatEngine** (singleton): loads Compustat quarterly, computes all accounting controls (Size, TobinsQ, ROA, BookLev, CapexAt, DividendPayer, OCF_Volatility), winsorizes at 1%/99% by fiscal year, caches
   - **CRSPEngine** (singleton): loads CRSP daily stock files by year, computes StockRet/MarketRet/Volatility over inter-call windows, winsorizes at 1%/99% by calendar year, caches; also provides `get_raw_daily_data()` for event-window calculations
   - **LinguisticEngine** (singleton): loads Stage 2 linguistic variables, caches

3. **Panel builder** (`build_h7_illiquidity_panel.py`):
   - Loads manifest (file_name, gvkey, ff12_code, start_date)
   - Builds 15 variable blocks via dedicated builders
   - Merges all on `file_name` (left join, zero row-delta enforced)
   - Assigns industry sample (Main / Finance / Utility)
   - Attaches fyearq_int from Compustat
   - Saves `h7_illiquidity_panel.parquet`

4. **Runner loading** (`run_h7_illiquidity.py`):
   - Loads panel parquet, selecting 22 columns
   - Builds `cal_yr`, `cal_qtr`, `cal_yr_qtr` via `build_cal_yr_qtr_index()`

5. **Sample filtering** (per specification):
   - Main sample filter (exclude FF12 = 8, 11)
   - Replace Inf/-Inf with NaN
   - Drop rows with missing DV
   - Complete-case filter (all required vars non-NaN)
   - Minimum 5 calls per firm

6. **Regression estimation**:
   - PanelOLS with firm-clustered SEs
   - 6 specifications varying FE type and control set
   - One-tailed p-values computed from two-tailed

7. **Table generation**:
   - `generate_all_tables.py` entry for H7 produces the publication-ready LaTeX table

## H. OUTLIER AND MISSING DATA TREATMENT
------------------------------------------------------------------------

### H1. Winsorization

**Compustat variables** (Size, TobinsQ, ROA, BookLev, CapexAt, OCF_Volatility):
- Level: 1%/99% by fiscal year
- Applied at: CompustatEngine level (`_winsorize_by_year` in `_compustat_engine.py`, line 1232 — bulk loop in `_compute_and_winsorize()` applying per-year 1%/99% to all `COMPUSTAT_COLS`)
- Min obs per year group: 10

**CRSP inter-call window variables** (Volatility):
- Level: 1%/99% by calendar year
- Applied at: CRSPEngine `get_data()` level (`winsorize_by_year` in `_crsp_engine.py`, line 445)

**DV and pre-call control** (delta_amihud, pre_call_amihud):
- Level: 1%/99% by calendar year
- Applied at: AmihudChangeBuilder level (`amihud_change.py`, lines 106--112)
- Rationale: delta_amihud is extremely right-skewed (skew ~162, kurtosis ~29K unwinsorized) due to micro-cap stocks with near-zero dollar volume

**Linguistic IVs** (all 5 `*_Uncertainty_pct` variables):
- 0%/99% upper-only per-year winsorization at LinguisticEngine level (`_linguistic_engine.py` lines 254-258, `winsorize_by_year(..., lower=0.0, upper=0.99, min_obs=10)`). The 0% lower bound is a no-op since values are >= 0 by construction, but the 99% upper bound clips extreme values per year.

**StockPrice, Turnover**:
- Not explicitly winsorized in their respective builders

**DividendPayer**:
- Not winsorized: binary indicator

### H2. Missing Data Policy

- Complete-case deletion: rows dropped if any required variable is NaN (`prepare_regression_data()` line 203)
- Inf/-Inf replaced with NaN before regression (`prepare_regression_data()` line 192)
- Minimum valid trading days: pre-window requires >= 2 valid days, post-window requires >= 2 valid days (`amihud_change.py`, MIN_PRE_DAYS=2, MIN_POST_DAYS=2; effective min = `max(1, window_days - 1)` = 2)
- Dollar volume of zero replaced with NaN to avoid division-by-zero Inf (`amihud_change.py` line 318)

### H3. Transformations

- `Size`: natural log of total assets (ln(atq))
- No centering, z-scoring, or other transformations applied to IVs or other controls
- `delta_amihud` daily illiquidity scaled by 1e6 (standard Amihud scaling)

## L. KNOWN ISSUES AND NOTES
------------------------------------------------------------------------

1. **TobinsQ formula discrepancy between docstring and code**: The `TobinsQBuilder` docstring (line 24) states `(AT + cshoq*prccq - CEQ) / AT`, but the actual CompustatEngine code (`_compustat_engine.py` line 988) computes `(cshoq*prccq + dlcq + dlttq) / atq` (market cap + book debt) / total assets. The code is the source of truth.

2. **StockPrice and Turnover not winsorized**: These two extended controls are computed via raw CRSP data in their respective builders but are not passed through any winsorization step. The other CRSP-derived variable (Volatility) is winsorized at the CRSPEngine level because it goes through `get_data()`, but StockPrice and Turnover use `get_raw_daily_data()` which returns unwinsorized daily records.

3. **Amihud scaling factor**: The daily illiquidity formula in AmihudChangeBuilder uses a 1e6 scaling factor (`amihud_change.py` line 319), consistent with the standard Amihud (2002) convention. The CRSPEngine's own inter-call Amihud computation (`_crsp_engine.py` line 256) also uses 1e6 scaling.

4. **Event-window reference date**: The AmihudChangeBuilder uses the last trading day on or before the call date as the reference point (line 328--331), then computes trading-day positions relative to this reference. Pre-window = trading days with rank 1 to `window_days` (default 3) before reference; post-window = trading days with rank 1 to `window_days` after reference.

5. **Year-chunking for memory efficiency**: The AmihudChangeBuilder processes calls by calendar year to avoid memory explosion from cross-joining all calls with all CRSP daily records (`amihud_change.py` line 232). The same pattern is used by StockPriceBuilder and TurnoverBuilder.

6. **SUMMARY_STATS_VARS incomplete**: The summary stats list (runner lines 110--124) includes 14 variables but omits `StockPrice` and `Turnover` from the extended controls.

7. **pre_call_amihud as lagged DV proxy**: The control `pre_call_amihud` is not a true lagged DV (it does not use the prior call's delta_amihud), but rather captures the pre-event level of illiquidity for the same call. This is appropriate for an event-study change specification, as it controls for the baseline illiquidity level.

8. **Minimum trading days filter**: AmihudChangeBuilder requires min 2 valid trading days in each window (pre and post) with `window_days=3`. This is set via `min_pre = max(1, w - 1)` and `min_post = max(1, w - 1)` at line 281--282. Calls with fewer valid trading days in either window get NaN for both `delta_amihud` and `pre_call_amihud`.

9. **Runner docstring stale spec count**: The runner docstring (lines 7, 11) says "4 model specifications" and "4 columns in one table," but `MODEL_SPECS` has 6 entries (cols 5-6 were added for Calendar Year-Quarter FE specs). The provenance doc correctly reports 6 columns; the docstring is stale.
